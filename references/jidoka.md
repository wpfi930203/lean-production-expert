# 自働化（Jidoka · 安东 · 防错 · 5Why · 变化点）实操手册

## 2. 概念地基

**一句话定位**：自働化（Jidoka）＝"如果发生异常、延迟等，操作者能够停止生产线"，带来①生产 100% 良品 ②机械设备故障防止 ③省人（不需要监视设备）〔出处：4.看板应用；3.自工序完结〕。它与 JIT 并列为精益两大支柱，本册只讲自働化这一支。

| 概念 | 判据（怎么算它是它） | 易混淆点 / 什么不是它 |
|---|---|---|
| 自働化 | 异常时设备自动停线或人停线；含 100% 良品、故障防止、省人三收益 | ≠自动化（只是机器能自己动，不会在异常时停） |
| 安东 Andon | 流水线操作过程控制系统，异常时手动/自动激活寻求帮助与交流信息 | ≠报警灯；核心是"停线＋响应"机制 |
| 固定停止位 FPS | 一辆车长＋与下一车间距所形成的停线位置 | ≠随便哪里都能停；标准化作业须走到 FPS 才停 |
| 自工序完结 | 完成好自工序工作、不制造不良品、不让不良流到后工序 | ≠终检把关；它是把质量做进工序 |
| 三不原则 | 不接收、不制造、不传递缺陷 | ≠"有问题报告班长"就完事 |
| 良品条件 | 设计要件＋工艺要件＋制造要件，满足即能生产良品 | ≠作业标准；是"满足就能出良品"的条件集合 |
| 省人 | 通过作业/设备改善以一个人为单位节省人（显性） | ≠少人化；省人经不起台数变化 |
| 少人化 | 根据必要生产数，不降低生产性地由几人生产，可随台数增减人员 | ≠省人（隐性 vs 显性） |
| 防错 Poka-Yoke | 防止呆笨的人做错事的设计方法（愚巧法），新江滋生首创 | ≠培训＋惩罚；靠"从根因消除错误"而非"让人小心" |
| 红牌条件 | 能引致生产错误的常见条件（调整、工装更换、对称/不对称、快速重复等） | ≠不良现象本身；是"高风险作业条件" |
| 5Why | 反复问为什么直至找到根本原因的丰田问法（TPS 奠基者首创） | ≠随便问五次；要沿因果链穿越不同抽象层面 |
| 变化点管理 | 4M 发生变化时，变化点发生前后采取措施以保证安定制造良品 | ≠日常点检；是针对"变化"的未然防止 |

**关键判断**：异常必须停线——自働化定义就是"设备或作业存在异常时，自动停线（设备）或人为停线"；仅 **Run Stop 紧急时立即停**，其余情况在固定停止位(FPS)停〔出处：1.安东；3.自工序完结〕。"没有标准（没有正常、异常区别）的地方就没有改善。"

## 3. 方法/工具逐项展开

### 3.1 自働化（Jidoka）

- **定义/目的**：发生异常时设备或人自动/人为停线；生产 100% 良品，设备故障防止，不需监视设备（省人）。
- **触发条件**：异常被隐瞒、不良流到后工序、人被迫"监视"设备（第三次浪费）。
- **操作步骤**：
 1. 识别"异常"定义（设备异常、作业异常、品质异常）。
 2. 给设备/工位装"能停"的能力（自动停线或一键停线）。
 3. 定停线规则：Run Stop 紧急立即停；其余到 FPS 停。
 4. 停线后进入安东响应与 5Why 根因对策。
- **量化口径**：三收益定性——①生产 100% 良品 ②机械设备故障防止 ③省人（不需监视设备）。
- **判读与决策**：若停不下来或停了没人管 → 先补安东响应机制（§3.2）再谈自动化。
- **常见错误/反例**：把"设备能自动运转"当自働化；为了不停线把异常"绕过去"。
- **出处**：〔出处：4.看板应用；3.自工序完结〕

### 3.2 安东（Andon）系统与响应

- **定义/目的**：流水线操作过程控制系统；异常时手动/自动激活以寻求帮助与交流信息；让异常立刻可见、可响应、可停线。
- **触发条件**：异常发现晚、瞒报、需要跨工位支援。
- **操作步骤（响应 5 步）**：
 1. **拉暗灯** → 工位灯亮、暗灯板区域灯闪黄、区域音乐响。
 2. **班组长立即赶到着手解决**（听到音乐看板定位区域，走近看工位灯定位工位）。
 3. **生产线继续流动到固定停止位(FPS)**。
 4. 到达 FPS **未解决 → 停线**，暗灯板区域灯继续闪黄、线名(Trim 3)闪红、**停线计时钟启动**。
 5. **问题解决 → 再拉一次暗灯线复位** → 暗灯板转绿、音乐停止、线恢复。
- **量化口径**：
 - FPS ＝ 一辆车长 ＋ 与下一车间距
 - 只有 **Run Stop 才立即停线**，其余为保护标准化作业在 FPS 停
 - 暗灯板 5 类：工段板 / 车间状态板 / 绩效板 / 终线流程板 / 维修板；关键字段含区域/工位号、停线计时钟、拉动次数、Goal/Actual/Trend/Quality/Downtime
- **判读与决策**：
 - **拉动暗灯不是负面事件**，是持续改善的机会。
 - 聚焦**拉动次数最多**的暗灯（高频＝根本原因未解决），而非只盯长停线的那次。
- **常见错误/反例**：把暗灯当成"惩罚按钮"、员工怕拉；只看停线总时长不看拉动频次；拉到 FPS 还硬撑不停。
- **出处**：〔出处：1.安东〕

### 3.3 管理板（目视化管理）

- **定义/目的**：目视化管理（VM）＝一眼即知、借眼睛视察就能看出异常所在；管理板是现场管理与 JIT 工具的有效载体。
- **触发条件**：现场看不出好坏、信息散在纸上/嘴里、异常要问才知道。
- **操作步骤**：
 1. 确定要管的内容（PQCDSM 六方面：效率/质量/成本/交期/安全/士气）。
 2. 分固定/动态两类做板。
 3. 按层级建三级看板（班组—车间—厂，语料称"三级看板"）。
 4. 定更新频率与责任人，异常一眼能看出。
- **量化口径**：管理板关键字段——PQCDSM、车间名称、人员信息、设备名称、作业标准〔出处：2.管理板〕。
- **判读与决策**：板上看不出异常（无目标/实际/趋势）→ 该板失效，重做。
- **常见错误/反例**：把管理板做成"装饰墙"；只贴结果不贴目标与趋势。
- **出处**：〔出处：2.管理板〕

### 3.4 自工序完结与三不原则

- **定义/目的**：完成好自工序工作、不制造不良品、不让不良流到后工序；制造质量维持管理的基础。
- **触发条件**：靠终检把关、不良流到后工序、返修增多。
- **操作步骤（推进 7 步骤）**：
 1. **项目明确化与共享化**
 2. **整理管理要素**（管理规定 / 点检表 / 作业标准）
 3. **按工序制订易遵守的工具**
 4. **制作管理板目视化**
 5. **监督与指导**
 6. **评价·改善**
 7. **日常维持**
- **量化口径/要素**：
 - 三类完结：部件完结 / 总成件完结 / 机能完结
 - 要素：管理规定 ＋ 作业标准 ＋ 点检表
 - 良品条件 ＝ 设计要件 ＋ 工艺要件 ＋ 制造要件
 - 三不原则：不接收、不制造、不传递缺陷（"Do not accept, build, or pass a defect"）
 - 管理板内容：管理规定、推进计划、作业标准、熟练度评价表、条件点检表、自工序完结率推移图、我的质量宣言
 - 配套 QA 网络表：发生防止/流出防止、工序保证度
- **判读与决策**：不良流到后工序 → 先查该工序的良品条件是否齐备、点检表是否执行；不齐则回步骤 2。
- **常见错误/反例**：靠判别检验/挑选挑不良（事后补救）；管理要素只写作业标准、缺点检表与管理规定。
- **出处**：〔出处：3.自工序完结；1.安东〕

### 3.5 少人化 vs 省人化

- **定义/目的**：省人＝显性，以一个人为单位节省人；少人化＝隐性，根据必要生产数不降生产性地由几人生产、可随台数增减人员。
- **触发条件**：产量增减要弹性调人、单元生产排班、要求"几人也能做"。
- **操作步骤**：
 1. 用节拍集合/连结方式把同节拍工序连起来。
 2. 用多能工支撑岗位轮换与人数增减。
 3. 按必要数算人工，不按设备台数配人。
- **量化口径**：
 - `必要人工(人工/班) ＝ 必要数/班 × Σ(CT＋附带工时) ÷ 稼动时间/班`
 - 同节拍连结示例：A 部品加工线（4.5 人工、节拍 60″）＋A 部品组装线（4.6、60″）＝9.1 人工，10 人→9 人
 - 混流示例：3 条专用线通用化 X 通用线 T/T＝27″、4.7 人工，6 人→5 人
- **判读与决策**：若减少一台数就得整班裁人 → 说明只是省人不是少人化；转向按必要数弹性配人。
- **常见错误/反例**：**线外支援撤销后正作业员恢复原速导致再次延迟** → 要缩短瓶颈机械循环时间（如 30 秒→25 秒）持久解决，而不是靠临时支援。
- **出处**：〔出处：4.少人化〕

### 3.6 防呆防错（Poka-Yoke）

- **定义/目的**：防止呆笨的人做错事的设计方法（愚巧法）；从根因消除错误，而非靠"培训＋惩罚"。
- **触发条件**：同类人为错误反复发生、红牌条件场景、要靠检查挑不良。
- **操作步骤（防错 7 步法）**：
 - **第 0 步** 心理准备；
 - **第 1 步** 识别和描述缺陷/红牌条件；
 - **第 2 步** 缺陷分析确定根本原因（因果图＋5Why）；
 - **第 3 步** 提出防错方案（4 种方法：信息加强 / 接触 / 计数 / 动作顺序）；
 - **第 4 步** 评估选择可行方案（成本/效益、防错装置选择标准）；
 - **第 5 步** 方案实施（用"恶心的试验"验证）；
 - **第 6 步** 运行和评估（PPAP 验证）；
 - **第 7 步** 标准化和推广。
- **量化口径/原理**：
 - **防错十大原理**：1 断根 2 保险 3 自动 4 相符 5 顺序 6 隔离 7 复制 8 层别 9 警告 10 缓和
 - **五大基本思路（按好坏排序）**：排除 ＞ 替代 ≈ 容易/简化 ≈ 异常检出 ＞ 缓和影响
 - **红牌条件**：调整、工装更换、对称/不对称、快速重复等
 - 防错装置选择标准：便宜（**500 元以下**）、设计精巧、易用好使
 - 核心判据：**所有的缺陷由错误产生；不是所有的错误都产生缺陷**；无意识的错误不可避免
- **判读与决策**：能用"排除/断根"就不要用"警告"（警告最弱）；方案要在第 5 步用"恶心的试验"验证。
- **常见错误/反例**：靠"培训与惩罚"防人为错误；只做判别检验（事后挑选）；防错装置贵而不好用。
- **出处**：〔出处：5.防呆防错〕

### 3.7 5Why 分析法

- **定义/目的**：从结果着手、沿因果链顺藤摸瓜、穿越不同抽象层面直到根本原因；防再发。
- **触发条件**：问题解决后又复发、对策只停在异常处置。
- **操作步骤**：
 - **把握现状 5 步**：①识别问题 ②阐明问题 ③分解问题 ④查找原因要点(PoC) ⑤掌握问题倾向（谁/哪一个/什么时间/多少频次/多大量）。
 - **原因调查**：识别确认直接原因 → 问 5Why 建立"原因/效果链" → 确认根因（通过"因此"检验）。
 - **问题纠正**：先用临时措施遏止，再用纠正措施处理根因，最后跟踪核实。
- **量化口径/模型**：
 - 问题冰山：现象 → 一次因/近因 → n 次因/远因 → 根因
 - 系统三问 M/O/S：为什么会发生（制造）／为什么流出（检验）／为什么系统允许（过程/职责/资源）
- **判读与决策**：对策若无法防止再发 → 根因没到，继续问；每个"为什么"与答案之间必须有**必然关系**。
- **常见错误/反例**：
 - 用借口式答案（"作业方法没有明确""要做的事太多""社长小气!"）→ 推不出再发防止对策；
 - 问到自己心理面（"担当者很忙""作业者心情烦躁"）→ 导不出对策；
 - 跳步、层间无必然关系 → 分析不充分；
 - 现象栏写推论而非事实 → 分析基础错误（应只记事实，三现原则）。
- **出处**：〔出处：6.5Why〕

### 3.8 变化点管理（4M）

- **定义/目的**：4M 发生变化时，变化点发生前后采取措施以保证安定制造良品；日常维持管理中对"变化"做未然防止。
- **触发条件**：换人、换料、换机、换法、试作、计划变更。
- **操作步骤（3 步骤）**：
 1. **变化点管理项目一览表作成**（从 4M 提出变化点 → 定措施内容/频率/实施者 → 定预定计划 → 定确认者）；
 2. **决定运用规则**（明确联系流程、定实施决定的责任人）；
 3. **准备共享情报的手段**（变化点管理板）。
- **量化口径/要素**：
 - 4M ＝ 人(Man)、设备(Machine)、物(Material)、方法(Method)；变化点 ＝ 计划中的变化 ＋ 突发性的变化
 - **三要点**：①确认能否满足制造良品条件 ②确认品质水平不低于变化前 ③确认防止不良流出后工序
 - 管理板 4 项目：①当日的变化点和措施 ②变化点的定义和措施 ③当日的人员配置 ④技能评价表
- **现场动作（每日）**：早会共享变化点 → 首件确认（作业/检查顺序/首件）→ 1 小时后状况确认 → 记录结果 → 保存报告书和记录。
- **判读与决策**：变化点当日未确认首件 → 停。
- **常见错误/反例**：**中断作业离席不做标识** → 发生工序遗漏；**试作品不做明示** → 混入量产品（应做明示、处理前后数量一致）。
- **出处**：〔出处：7.变化点管理〕

## 4. 公式与指标速查

| 指标 | 公式 | 好的基准 | 坏的信号 | 出处 |
|---|---|---|---|---|

## 5. 打法（组合拳）

**打法 1：不良流到后工序（终检挑不完）→ 自工序完结＋防呆＋安东 三件套**
- 第 1 步（立条件）：对该工序做自工序完结 7 步骤——明确项目 → 整理管理要素（管理规定/点检表/作业标准）→ 定良品条件（设计＋工艺＋制造要件）。**产出物：良品条件＋点检表。**
- 第 2 步（防住错）：用 Poka-Yoke 7 步法定根因，按五思路优先选"排除/断根"，装置按 500 元以下/精巧/易用好使选型；第 5 步用"恶心的试验"验证。**产出物：防错装置＋验证记录。**
- 第 3 步（暴露）：在该工位设安东，异常即拉灯，走到 FPS 未解即停线；停线计时钟启动、班组长响应。**产出物：安东响应规则＋停线记录。**
- 第 4 步（固化）：纳入管理板目视化（自工序完结率推移图、QA 网络表），监督—评价—维持。**产出物：管理板＋维持机制。**
- 判读：若有不良流过后工序 → 先查第 1 步良品条件与点检表是否齐备；齐备仍流出 → 查第 2 步防错是否覆盖该失效模式。

**打法 2：异常瞒报/发现太晚 → 安东＋管理板＋5Why**
- 第 1 步（让人敢拉）：立"拉动暗灯是改善机会、不是负面事件"的规则，明确 FPS 与"仅 Run Stop 立即停"。**产出物：安东运行规则。**
- 第 2 步（让异常可见）：上暗灯板（区域/工位/计时钟/拉动次数/Goal-Actual-Trend），配合管理板 PQCDSM。**产出物：暗灯板＋管理板。**
- 第 3 步（找真因）：对拉动次数最多的暗灯做 5Why（系统三问 M/O/S），对策防再发并标准化。**产出物：5Why 分析表＋对策。**
- 判读：只盯长停线不盯高频拉动 → 根本原因会一直不解决。

**打法 3：同类人为错误反复犯 → 防呆＋变化点管理**
- 第 1 步（认错）：承认"人民的错误是自然事件、无意识错误不可避免"，放弃"培训+惩罚"路线。
- 第 2 步（防错）：按红牌条件（调整、工装更换、对称/不对称、快速重复）逐条做 Poka-Yoke，优先排除类。**产出物：红牌条件清单＋防错方案。**
- 第 3 步（管变化）：把"换人/换料/换机/换法/试作/中断作业"纳入 4M 变化点管理表，当日首件确认＋1 小时后确认。**产出物：变化点管理表＋管理板。**
- 判读：错误仍发生 → 回第 2 步，检查是否只用了"警告"等弱等级防错。

**打法 4：产量波动要弹性配人 → 少人化＋多能工＋自工序完结**
- 第 1 步（算人）：按 `必要数/班 × Σ(CT＋附带工时) ÷ 稼动时间/班` 算必要人工，把同节拍工序"连结"。**产出物：必要人工表＋节拍连结图。**
- 第 2 步（养人）：多能工培养（得星表/ILU），支撑轮岗与人数增减。**产出物：得星表＋训练计划。**
- 第 3 步（稳质）：人数变动时用自工序完结＋变化点管理守住质量（人变了是最大变化点）。**产出物：变化点管理表。**
- 判读：支援一撤就再次延迟 → 缩短瓶颈机械循环时间持久解决，而非临时加人。

## 6. 案例（保留数据）

**案例1：TPS 奠基者 5Why（机器停机）**〔出处：6.5Why〕
- 机器停了 → 超负荷保险丝断 → 轴承润滑不够 → 润滑泵吸不上油 → 油泵轴磨损松动 → **没有安装过滤器混进铁屑**。
- 对策：在油泵轴上安装过滤器。可迁移点：一层层问到"设计/管理面"才出得了再发防止对策。

**案例2：A 车间地板上有一滩油**〔出处：6.5Why〕
- 漏油 → 衬垫非预期磨损 → 新采购衬垫质量未达要求 → **采购只考虑报价** → 采购部绩效考核标准太偏重降低短期成本。
- 对策：调整绩效考核指标（质量合格率＋成本降低率）。可迁移点：根因常落在**管理制度/考核**面，非作业者。

**案例3：杰弗逊纪念馆墙面破损**〔出处：6.5Why〕
- 墙面破损 → 用强化学清洗液清洗 → 清除大量鸟粪 → 聚集大量鸟 → 鸟吃蜘蛛 → 蜘蛛吃昆虫 → **昆虫被黄昏灯光吸引**。
- 对策：天未黑前拉上窗帘。可迁移点：跳不出"清洗墙面"的思维，就找不到"拉窗帘"的廉价根治。

**案例4：香皂空盒 vs 乡镇肥皂厂**〔出处：5.防呆防错〕
- 世界 500 强：加称重装置自动剥离超差包装盒（投入大）。乡镇企业：班长用一台电扇把空盒吹下流水线。
- 启示：防错不一定要高投入，"便宜（**500 元以下**）、设计精巧、易用好使"是防错装置选择标准。

**案例5：FIFO 失效后果（对照自働化必要性）**〔出处：9.先进先出〕
- 未做 FIFO 的量化后果：劣化部件必须废弃、购入费用损失、完工品价格上升、售出后发生埋怨或重大灾害、公司信誉与社会信赖损失；不良时"再调查查找、返修上耗费没有价值的时间增加了"。
- 可迁移点：质量保证链一旦断（无 FIFO/无完结），自働化的"100% 良品"即失守。

## 9. 本册证据缺口

- **自働化的机械/电气实现细节缺失**：语料侧重管理规则（何时停、谁响应），未见自动停线装置选型、防错与自动化接口的技术内容。
- **安东系统的技术规格缺失**：暗灯板尺寸、扬声器布局参数、数据采集接口格式等，语料只给原则性描述。
- **防错装置成本效益的量化模型缺失**：仅有"500 元以下"等定性选择标准，无投入产出量化模型。
- **5Why 的完整案例体系不完全**：语料给 4 个案例（机器停机/地板油/纪念馆墙面/香皂空盒），但"系统三问 M/O/S"在案例中的完整映射未逐一展开。
- **变化点管理与自工序完结的边界**：两者在 `7.变化点管理` 与 `3.自工序完结` 中均有"日常维持"表述，交集部分的职责划分语料未完全澄清。
- **少人化与多能工的训练量化标准**：`4.少人化` 讲手法与节拍集合，多能工的训练量化在 `6.多能工`（属 JIT 分册语料），本册未展开具体课时/合格判定阈值。
- **本模块未覆盖**：安东系统与 MES/SCADA 的数据集成规范、防错装置的电气安全标准、AI 视觉防错的判定阈值设定。
- **不可用源文件**：无（本模块 7 份语料全部可读，均精读）。

# 02-tools · 工具地图：选型逻辑 / 思维归属 / 边界与误用

> **本文件定位**：它是 `lean-production-expert` master skill 的"工具地图"调研稿，与 01–09 号分册**互补而非重复**。
> - 分册（01–08）已给**每个工具的操作参数、公式、判读阈值、六格卡（定义/触发/步骤/量化/判读/失败）**——那是"怎么用"。
> - 本文件只回答 master skill 结构上**缺失的三层**：
>   1. **选型逻辑**：面对具体问题，资深人如何判断"该用哪个工具、为什么不选另一个"（诊断路径）。
>   2. **思维归属**：每个工具背后代表哪种思想流派，用了它等于默认接受了什么假设。
>   3. **边界与误用**：什么情况下**不该用**，用了它会**掩盖什么真实问题**（最高价值层）。
>
> **使用约定**：凡涉及"操作参数 / 计算公式 / 判读阈值"，本文件不展开，统一交叉引用对应分册（见各工具卡片末的"操作参数见分册 XX"）。本文件只给"何时用 / 何时不用 / 背后假设"。
>
> **来源标注约定**：每条关键判断后标注 `[丰田官方]` / `[学术/标准]` / `[行业实践]` / `[推断]`。

> - `[行业实践]`：业界广泛采用的规则与阈值（非单一权威出处，引用时需说明是"常见提法"）。

## 1. 工具清单（按功能域，每工具六字段 + 思维归属）

> 字段：① 工具名（中英文）｜② 真正解决的机制 ＋ ③ 默认接受的假设（思维归属）｜④ 触发条件（信号/数字）｜⑤ 前置依赖｜⑥ 不该用 / 误用形态｜⑦ 它掩盖了什么。
> ⑥、⑦ 为本文件最高价值字段。

### 1.1 价值流层

**价值流图 / 物与情报流程图（VSM / Material & Information Flow）** `[丰田官方]`/`[学术/标准]`
- ②真正解决：把"整个价值流里的停滞"从不可见变成可测量——用库存三角把在制品换算成时间，暴露增值时间占比（增值比常 <5%，多数离散制造 `[推断]`）。
- ③默认假设：价值流存在可识别的"客户节拍"与"信息流/物流双线"，且改善应从系统层（全局）而非局部工序入手。
- ④触发：交期长、但没人说得清时间耗在哪；或局部效率很高、整体 L/T 却降不下来。
- ⑤前置：有客户需求数量与可用时间（算 T/T）；能进现场量 C/T、C/O、在制量。
- ⑥不该用/误用：把它画成"架构漂亮图"然后归档——**VSM 不驱动改善就是墙上的装饰**；只画信息流不画物料流，或反之；不区分现状图与未来图。
- ⑦掩盖：它只"暴露"问题，不"解决"问题。画完若无后续未来图与改善爆发点，会让人误以为"已经做了精益"。
- 操作参数见分册：`01 lean-system.md`（物与情报流程图 7 观察点、L/T 三版分解）。

**当前状态图 vs 未来状态图（Current / Future State）** `[丰田官方]`
- ②真正解决：未来图强制回答"超市放哪、看板怎么流、均衡柜在哪、哪段先爆改"，把改善目标具象化。
- ③默认假设：现状可被有意义地重构；存在一个比现状明显更优的"未来"。
- ④触发：已画现状图、找到最大停滞段，需锁定改善方向。
- ⑤前置：现状图已画、T/T 已算、瓶颈已定位。
- ⑥不该用/误用：现状图没画就画未来图（空中楼阁）；未来图不单独画、与现状图混在一起。
- ⑦掩盖：未来图美好愿景会让人忽略"现状为何如此"的根因，跳过 SDCA 维持直接跳 PDCA。

**价值流分析（Value Stream Analysis）** `[学术/标准]`
- ②真正解决：用增值/非增值时间分解，量化"浪费占比"，把改善立项从"感觉"变成"年化金额"。
- ③默认假设：活动可分为增值与非增值，非增值皆可质疑。
- ④触发：需要向管理层证明某段流程有多少时间是停滞。
- ⑤前置：VSM 数据（C/T、换型、在制）。
- ⑥不该用/误用：用"增值比"横向比不同行业（流程业与离散业不可比）。
- ⑦掩盖：增值比低看起来都很糟，会让人平均用力，忽略关键瓶颈段。

**价值流管理（VSM as Management / Lean Value Stream Management）** `[行业实践]`
- ②真正解决：把 VSM 从一次性项目变成"按节拍评审、按未来图追踪"的日常管理机制。
- ③默认假设：价值流需要长期 Owner 与节奏化复盘，否则反弹。
- ④触发：VSM 项目做完 3 个月后回潮。
- ⑤前置：已有现状/未来图、有跨部门 Owner。
- ⑥不该用/误用：把 VSM 管理做成月度 PPT 汇报，无现场点检。
- ⑦掩盖：管理动作掩盖了"现场标准未固化"的事实。

### 1.2 时间与流动层

**节拍时间（Takt Time, T/T）** `[丰田官方]`
- ②真正解决：把"客户需求速率"变成一条可对照的基准线——任何工序 C/T > T/T 即为瓶颈 `[丰田官方]`（丰田："make at the pace at which they're sold"）。
- ③默认假设：需求是相对平稳、可计算的；节拍是"被客户拉动"的，不是"设备产能"决定的。
- ④触发：不知道该按多快生产；或各工序自顾自赶工。
- ⑤前置：可用工作时间、客户需求量（非产能）。
- ⑥不该用/误用：用设备最大产能当节拍（这是"产能节拍"不是 T/T）；需求剧烈波动时硬算单一 T/T 误导排产。
- ⑦掩盖：T/T 是平均值，掩盖了需求波动与换型损失——单看 T/T 会忽略平准化与 SMED 的必要性。

**线平衡 / 山积图（Line Balancing / Yamazumi）** `[行业实践]`
- ②真正解决：把各工序 C/T 叠成山积，暴露"最慢工序=瓶颈"与"工序间等待"，用重排/重分配消除线内等待。
- ③默认假设：工作量可在人之间重分配；产品/工艺相对标准化。
- ④触发：编成效率 <90%（行业常见目标 `[行业实践]`）；线内大量在制品堆积在某一站。
- ⑤前置：已测各工序 C/T、已知 T/T、有标准作业。
- ⑥不该用/误用：在换型损失 >30% 时先搞平衡（换型会把平衡打碎 `[推断]`）；用"平均 C/T"做山积（应看实际分布）。
- ⑦掩盖：线平衡只解决"等待"，不解决"加工本身慢"与"换型/质量"问题——平衡好了但换型长，整体仍慢。
- 操作参数见分册：`01 lean-system.md`、`05 shopfloor-teams.md`（编成效率公式）。

**单件流（One-Piece Flow）** `[丰田官方]`
- ②真正解决：把批量生产中的"在制库存+搬运+等待"彻底消除，让缺陷立即暴露、L/T 极短。
- ③默认假设：工序可就近布置、换型足够快、质量足够稳——单件流是"结果"不是"出发点"。
- ④触发：在制高、流经多家车间、质量问题发现晚。
- ⑤前置：SMED 已压、质量稳定（自工序完结）、布局可调。
- ⑥不该用/误用：换型没压就强推单件流 → 换型损失吞噬所有收益；设备大型不可移动硬做单件流。
- ⑦掩盖：单件流把"批量掩盖的换型/质量波动"暴露出来，若没先治本，会把线搞垮而非改善。

**单元生产（Cell Production / U-cell）** `[行业实践]`
- ②真正解决：用 U 型单元让人可操作多工序，支撑少人化与弹性。
- ③默认假设：需求量与品种组合允许一个单元闭环；人可多能工。
- ④触发：多品种小批量、直线布局导致大量搬运与在制。
- ⑤前置：单件流可行、多能工到位、标准作业清晰。
- ⑥不该用/误用：大批量单一品种也硬改单元（直线更经济）；无多能工就改单元（人不会补位）。
- ⑦掩盖：改布局不改革管理，单元内仍各自为政。

**一个流（One Flow，连续流）** `[丰田官方]`
- ②真正解决：工序间零库存、零等待的连续流动，是 JIT 的终极形态之一。
- ③默认假设：上游节拍=下游节拍且稳定（平准化）。
- ④触发：已实现单件流、节拍已平准、仍想进一步压在制。
- ⑤前置：单件流 + 平准化 + 拉动均已就位。
- ⑥不该用/误用：在波动大、换型慢时追求"绝对一个流"。
- ⑦掩盖：一个流对上游波动零容忍，会放大任何不稳定。

**生产节拍与同步（Pacemaker / Synchronization）** `[丰田官方]`
- ②真正解决：定一个"节拍工序（pacemaker）"统一拉整个价值流的节奏，避免各段自顾自。
- ③默认假设：存在一个可定义的下令点，下游需求能规则地向上传递。
- ④触发：多段生产节奏错乱、前端过量后端断料。
- ⑤前置：T/T 已知、VSM 已画、超市位置已定。
- ⑥不该用/误用：节拍工序定在离客户最远的环节（应靠近客户端）。
- ⑦掩盖：同步只管节奏，不管"是否做了对的产品"（需平准化配合）。

### 1.3 换型与批量层

**SMED 快速换模（Single-Minute Exchange of Die）** `[学术/标准]`
- ②真正解决：把换型时间从"小时级"压到"单分钟级"（single-digit minute，即 <10 分钟 `[学术/标准]`，Shingo《A Revolution in Manufacturing: The SMED System》1985），通过内/外作业分离、转内为外、并行化，从而允许小批量、降在制。
- ③默认假设：**换型时间是可压缩的、是浪费而非必然成本**；换型活动可被外部化与并行化。
- ④触发：换型损失占工序时间 >30%（`[推断]` 启发式）；大批量是为换型被迫而非为经济。
- ⑤前置：能区分内/外作业；有基本标准作业观念。
- ⑥不该用/误用：**只做"内作业"压缩不做"外作业"**（治标，天花板低）；把"机器停到开"当换型（真换型=上一件良品到最后一件良品）；为压换型而牺牲质量（调机参数未标准化）。
- ⑦掩盖：SMED 只缩换型，不解决"换的是否为对的产品"（需平准化）；也不解决质量不稳。
- 操作参数见分册：`02 jit.md`、`08-B rollout-tools-execution.md`（SMED 八步）。

**换型标准作业（Changeover Standard Work）** `[行业实践]`
- ②真正解决：把换型步骤固化，防止 SMED 成果反弹、依赖"老师傅手感"。
- ③默认假设：换型可被标准化并传授。
- ④触发：SMED 改善后 3 个月回潮、换型时间波动大。
- ⑤前置：已完成 SMED 改善、动作已分解。
- ⑥不该用/误用：没做 SMED 就写换型标准（标准建立在低效现状上）。
- ⑦掩盖：标准换型不解决"为什么换这么频繁"（品种/批量策略问题）。

**内外部作业分离（Internal/External Setup Separation）** `[学术/标准]`
- ②真正解决：识别"必须停机才能做"（内）与"可停机前/后做"（外），把外作业移到停机窗口外，直接缩短停机时间。
- ③默认假设：多数"以为必须停机"的动作其实可在运行中准备。
- ④触发：换型时间长且准备物料/工具在停机时才做。
- ⑤前置：能观测完整换型过程。
- ⑥不该用/误用：分离后不做"转内为外"（仅分离不优化，收益有限）。
- ⑦掩盖：分离不解决设备/夹具本身的换型设计缺陷。

### 1.4 拉动与库存层

**看板体系（Kanban System）** `[丰田官方]`
- ②真正解决：用"后工序取走、前工序才补"的实体信号，把推动变成拉动，自动限制在制、暴露异常。
- ③默认假设：**需求可预测且相对平稳**（需平准化支撑）；过程稳定、换型已可控；供应商/前工序可信赖。
- ④触发：在推动式排产下库存高且仍断线；想在制自动 capped。
- ⑤前置：T/T、换型已压、平准化、标准作业、超市可控。
- ⑥不该用/误用：**做成展示看板（失去取/补信号闭环）**；**没做平准化就硬拉**（波动冲击上游）；**用看板张数倒推库存而不做需求波动分析**；**为 JIT 而 JIT 忽略供应商交付稳定性**。
- ⑦掩盖：看板让在制"看起来受控"，但若需求波动大、换型未压，它只是把混乱限制在更小的缓冲里，并未消除根因。
- 操作参数见分册：`02 jit.md`（看板张数公式）、`08-B`。

**超市（Supermarket）** `[丰田官方]`
- ②真正解决：在工序间设"前工序的成品店"，后工序按需取，前工序按取走量补，切断推动链。
- ③默认假设：品种/用量足以支撑一个"店"的经济批量；存取规则可被执行。
- ④触发：前后工序节奏不一、在制堆积且不清。
- ⑤前置：看板信号、FIFO 能力、补货规则。
- ⑥不该用/误用：品种过多开不了超市（应改按单/按序）；超市位置离取料点太远（变回仓库）。
- ⑦掩盖：超市把"前后工序不同步"局部吸收，若不同步根因不除，超市会被撑爆或掏空。

**拉动信号（Pull Signal / Replenishment Trigger）** `[丰田官方]`
- ②真正解决：定义"何时补、补多少"的触发规则（看板、空箱、MES 信号）。
- ③默认假设：信号能被即时、准确传递并执行。
- ④触发：补货靠人喊/经验，常多补或少补。
- ⑤前置：超市、补货规则、FIFO。
- ⑥不该用/误用：信号与实物脱节（有信号无货/有货无信号）。
- ⑦掩盖：信号系统完善但补货内容错（做了不对的产品）。

**补货规则（Replenishment Rule）** `[行业实践]`
- ②真正解决：用（补货周期 × 日均用量 + 安全库存）算该备多少，平衡缺料与积压。
- ③默认假设：需求与提前期可估计、波动可量化。
- ④触发：常缺料或常积压双现。
- ⑤前置：用量、提前期数据、需求波动分析。
- ⑥不该用/误用：**忽略需求波动**直接套 EOQ；安全库存拍脑袋。
- ⑦掩盖：补货规则优化不解决"为何提前期长"（供应商/内部换型）。
- 操作参数见分册：`04 supply-chain.md`（EOQ、安全库存、期量标准）。

**平准化 / 均衡化（Heijunka）** `[丰田官方]`
- ②真正解决：把品种/数量按节奏均匀排产，降低系统波动，使小批量拉动可行。
- ③默认假设：**需求可按某种规则被"平滑"**；上游有能力跟随平准排程。
- ④触发：天天插单、排产大起大落、上游被波动冲垮。
- ⑤前置：换型已压（否则平准=频繁换型自杀）、标准作业、看板。
- ⑥不该用/误用：换型没压先平准 → 频繁换型拖死产线；平准柜只是摆设不按柜取。
- ⑦掩盖：平准化平滑了"表象波动"，但若客户需求本身剧烈且不可约，平准只是把压力推给供应商。
- 操作参数见分册：`02 jit.md`、`04 supply-chain.md`（MPS/平准）。

**库存水位（Inventory Water Level / Cap）** `[行业实践]`
- ②真正解决：给在制/成品设上限，防止缓冲无限膨胀，迫使异常上浮。
- ③默认假设：存在"合理上限"，且超上限被视为问题信号。
- ④触发：在制持续超过超市容量、无人干预。
- ⑤前置：看板/超市、FIFO。
- ⑥不该用/误用：设上限但没"超了怎么办"的响应机制（只限不放）。
- ⑦掩盖：限了水位但根因（换型/质量/供应商）未治，水位常被"临时破例"突破。

**FIFO（先进先出）** `[丰田官方]`
- ②真正解决：保证物料按序消耗，防止老料滞留、混淆批次、掩盖停滞。
- ③默认假设：先到应先用；物料有保质期/版本序。
- ④触发：同一物料多批混放、先到的用不上。
- ⑤前置：定置、目视化。
- ⑥不该用/误用：有 FIFO 通道但被"就近拿"破坏；不标识批次。
- ⑦掩盖：FIFO 把好料坏料顺序管住，却掩盖"为何堆了这么多批"（上游过量）。

### 1.5 质量与自働化层

**自働化（Jidoka / Automation with a Human Touch）** `[丰田官方]`
- ②真正解决：让设备/人"一发现异常就停"，把质量内置进工序、不流出不良。
- ③默认假设：**异常应被立即停线暴露**，而非继续产出不良；停机比流出不良成本低。
- ④触发：不良流出到后工序/客户；设备带病运行。
- ⑤前置：能定义"什么是异常"、有停线授权与响应机制。
- ⑥不该用/误用：只装自动停机不给人停线权（自働化是"人+机"）；停了线没人响应（停而不改）。
- ⑦掩盖：自働化让停线频繁，若没配套快速响应（安灯/5Why），会"停得越多越乱"。
- 操作参数见分册：`02 jidoka.md`。

**安灯 / 异常响应（Andon）** `[丰田官方]`
- ②真正解决：异常可视化+升级机制，确保"停了之后有人来、限时解决"。
- ③默认假设：异常必须被看见并升级，响应有节奏（如丰田 FPS 规则）。
- ④触发：异常靠口头喊、响应无时限、重复发生。
- ⑤前置：已定义异常类型、有响应 SLA。
- ⑥不该用/误用：安灯只亮不行动（变成"警报墙"）；用 OEE/产量压过安灯（瞒异常抢产）。
- ⑦掩盖：安灯亮了响应了，但根因未用 5Why 闭环，异常会换件再发。

**自工序完结（Built-in Quality / Jibiki-kanryo）** `[丰田官方]`/`[行业实践]`
- ②真正解决：本工序"不接收/不制造/不流出"不良，把质量责任沉到源头。
- ③默认假设：质量源于源头，不靠后工序检验兜底（丰田："85% 质量问题源于管理不善"为行业常见提法 `[行业实践]`，非单一权威数字）。
- ④触发：后工序频繁挑前工序的不良；检验把关成主力。
- ⑤前置：标准作业、作业要领、变化点管理。
- ⑥不该用/误用：只喊口号无标准、无防呆；把"自检"当"自工序完结"（差"不流出"闭环）。
- ⑦掩盖：源头做了但标准作业本身错 → 错得一致，反而难发现。

**防呆防错（Poka-Yoke）** `[学术/标准]`
- ②真正解决：用装置/流程设计让"错不可能发生或一发生就停"，比靠人注意力可靠。
- ③默认假设：人會犯错是常态，系统应兜底而非苛责个人。
- ④触发：同一低级错误反复发生；依赖员工"小心"。
- ⑤前置：已知错误模式（FTA/鱼骨定位）。
- ⑥不该用/误用：防呆做成"提醒标签"（仍是人判断）；防呆增加操作负担被绕开。
- ⑦掩盖：防呆治标，不解决"为何会设计出易错工序"（需回到标准作业/工艺）。
- 操作参数见分册：`02 jidoka.md`（Poka-Yoke 7 步 10 原理）。

**源头质量检验（Source Inspection）** `[学术/标准]`
- ②真正解决：在缺陷产生点即时检、即时停，避免批量不良。
- ③默认假设：检验价值在于"阻止下流"而非"挑出废品"。
- ④触发：终端检验才发现大批不良。
- ⑤前置：可定位源点、有停线权。
- ⑥不该用/误用：把"首件检"当源头检验（只防首件不防过程漂移）。
- ⑦掩盖：源头检只管"本点"，跨工序系统误差仍会漏。

**5Why / A3 问题解决方法** `[丰田官方]`/`[学术/标准]`
- ②真正解决：沿因果链追问到可行动的根因，把对策从"现象"打到"系统"。
- ③默认假设：问题有可追溯的因果链，且根因在"管理/系统"层而非个人。
- ④触发：同一问题反复发生、对策只治标。
- ⑤前置：有真实数据、三现主义（现场/现物/现实）。
- ⑥不该用/误用：5Why 变成"为什么→因为人马虎"（归罪个人，停在表面）；A3 写成八股不行动；没数据靠脑补因果。
- ⑦掩盖：5Why 若前提数据错，会推导出"看似合理"的错根因。
- 操作参数见分册：`02 jidoka.md`、`03 hoshin-daily-5s.md`（A3 五步）。

### 1.6 标准与作业层

**标准作业（Standard Work）** `[丰田官方]`
- ②真正解决：把"当前最优做法"固定为节拍/作业顺序/标准手持三要素，是改善的基线（无标准无改善）。
- ③默认假设：**存在"当前最好"且可被记录传授**；标准应随改善而更新（活的标准）。
- ④触发：同一活不同人做法不一、质量波动。
- ⑤前置：T/T、已测 C/T、工序可定义。
- ⑥不该用/误用：标准写完不变（变僵化）；标准由工程师写、操作工不认；**先改善再标准化**（无基线改善无法验证）。
- ⑦掩盖：标准作业固化了"当前最优"，若当前本身含浪费，标准会保护浪费。
- 操作参数见分册：`02 jit.md`、`08-B`（组合票/山积表）。

**作业要领（Work Instruction / Key Points）** `[行业实践]`
- ②真正解决：在标准作业之上给"关键质量点/安全点"的操作细节，保质量一致性。
- ③默认假设：关键步骤需被特别强调且可执行。
- ④触发：标准作业太粗、关键工序仍波动。
- ⑤前置：标准作业已立。
- ⑥不该用/误用：把要领写成厚手册无人看。
- ⑦掩盖：要领详但标准作业错 → 错得更精致。

**点检（Checklist / Inspection Routine）** `[行业实践]`
- ②真正解决：把"该看的几样"固化成定时清单，防漏检、支撑维持。
- ③默认假设：关键状态可被离散点观测并判定。
- ④触发：设备/质量靠人记性、常漏项。
- ⑤前置：已知关键检查项与判据。
- ⑥不该用/误用："打钩式"点检（人不到场勾已打）；点检项过多失效。
- ⑦掩盖：点检合格 ≠ 过程稳定（点检是抽样不是连续控制）。
- 操作参数见分册：`04 tpm-equipment.md`（点检六定）。

**变化点管理（Change Point Management / 4M）** `[行业实践]`
- ②真正解决：对人/机/料/法变化点做预判与确认，防"变了才出事"。
- ③默认假设：变化是异常主源，变化可识别可管理。
- ④触发：换班/换模/换料后不良陡增。
- ⑤前置：标准作业、变化点清单。
- ⑥不该用/误用：只记录不确认；变化点定义过窄（漏法/环）。
- ⑦掩盖：管了变化点但标准本身弱，变化只是触发。
- 操作参数见分册：`02 jidoka.md`（变化点 4M）、`05 quality-management.md`（变更点 7 步）。

**OJT / 多能工（On-the-Job Training / Multi-skilling）** `[丰田官方]`/`[行业实践]`
- ②真正解决：在现场"先做给看→做给看→做做看"传递技能，支撑少人化与弹性。
- ③默认假设：技能靠现场带教而非课堂；多能是流动的前提。
- ④触发：一人一岗、请假即断线；减人无力。
- ⑤前置：标准作业清晰（否则教的是错的）。
- ⑥不该用/误用：**培训替代现场辅导**（课堂懂≠现场会）；多能工只"会"不"精"（得星表缺失）。
- ⑦掩盖：多能工掩盖了"工序本身设计冗余"（靠人补位而非流程改善）。
- 操作参数见分册：`03 rollout-talent.md`（OJD 四步、得星表）。

### 1.7 设备与保全层

**TPM 自主保全 / 计划保全（Autonomous / Planned Maintenance）** `[学术/标准]`
- ②真正解决：自主保全让操作工做清洁/紧固/润滑/点检（清紧固），把设备基本状态守住；计划保全做专业预防/修复。
- ③默认假设：**操作工对设备基本状态负责**；大部分故障前有征兆可预防。
- ④触发：设备老坏、保全人员被日常清洁拖死、OEE 低。
- ⑤前置：点检基准、故障数据。
- ⑥不该用/误用：自主保全做成"操作工扫地"（清紧固未做）；计划保全只修不预（ reactive）；自主/计划职责不清打架。
- ⑦掩盖：TPM 提升可用率，但性能/质量损失（微停、降速）仍可能被忽略。
- 操作参数见分册：`04 tpm-equipment.md`（自主七步、计划七步）。

**OEE（设备综合效率）** `[学术/标准]`
- ②真正解决：用 时间稼动率 × 性能稼动率 × 良品率 把设备损失三维度合一，暴露最弱项。
- ③默认假设：损失可被归到三类且同口径度量；分母是"计划运行时间"。
- ④触发：设备看着在转但产出低；不知损失在哪。
- ⑤前置：清晰的时间定义（计划/运行/负荷）、停机与良品数据。
- ⑥不该用/误用：**用 OEE 考核个人**（把人变看机器的，诱发瞒微停/抢产）；不同厂用不同时间口径横比；只看总数不拆三率。
- ⑦掩盖：OEE 高但"做了不对的产品"（有效产出低）看不出；OEE 是 KPI 不是诊断，根因仍需深挖。
- 数字诚实：OEE"世界级 >85%"源自 Nakajima《Introduction to TPM》(1988, Productivity Press) 的 0.90×0.95×0.99≈0.846≈85% 三项目标，**是拉伸目标而非调研中位数**；Nakajima 当时估计行业典型约 60% `[学术/标准]`。该阈值随行业差异大（连续流程业常 >90%，离散/多品种 65% 可能已优），**不可跨行业硬套**。
- 操作参数见分册：`04 tpm-equipment.md`（OEE 完整公式与算例）。

**快速换模与设备标准作业（SMED + Equipment Std）** `[学术/标准]`
- ②真正解决：把换模做成设备级标准动作，支撑小批量与 OEE 可用率。
- ③默认假设：换模是可标准化、可传授的设备活动。
- ④触发：换型占用可用时间高、波动大。
- ⑤前置：SMED 已做、点检基准。
- ⑥不该用/误用：换模标准与设备点检脱节。
- ⑦掩盖：换模快了但设备精度不足，良品率仍低。

**备件管理（Spare Parts Management）** `[行业实践]`
- ②真正解决：在"缺件停线"与"备件积压"间平衡，保障保全可执行。
- ③默认假设：关键件故障可预测、有合理库存策略。
- ④触发：关键件坏了等备件；或备件堆仓库。
- ⑤前置：故障数据、ABC 分类。
- ⑥不该用/误用：全量备（资金占压）；只备便宜件（关键件漏）。
- ⑦掩盖：备件充足掩盖"为何关键件老坏"（根因未治）。

### 1.8 现场与素养层

**5S / 6S** `[行业实践]`
- ②真正解决：整理(要/不要)→整顿(定位)→清扫→清洁→素养→(安全)，把"异常可见"的地基打好。
- ③默认假设：**标准能被维持**（素养层）；"要/不要"可被判定。
- ④触发：东西找不到、通道堵、红牌作战后仍能清。
- ⑤前置：有"要/不要"基准（如 30 天未用即移出 `[行业实践]`）；有日常管理维持。
- ⑥不该用/误用：**5S 做成大扫除运动**（季度突击后回潮）；只做前 3S 不做素养；为 5S 而 5S 不接目视/标准。
- ⑦掩盖：5S 干净 ≠ 流程对；现场整洁会让人误以为"管理好了"，真实停滞仍在。
- 操作参数见分册：`03 hoshin-daily-5s.md`（5S 六步、红牌、定置率、100 分表）。

**目视管理（Visual Management）** `[丰田官方]`
- ②真正解决：让状态/标准/异常"一眼可见"，把管理从"人脑记"变"现场看"。
- ③默认假设：信息应放在发生地、任何人能判读。
- ④触发：状态靠问、板子没人更新。
- ⑤前置：有标准、有判定基准。
- ⑥不该用/误用：做满墙图表但无"异常怎么行动"；目视=装饰。
- ⑦掩盖：目视板漂亮但数据假/过期，制造"一切正常"的假象。

**红牌作战（Red Tag Campaign）** `[行业实践]`
- ②真正解决：用红牌直观标记"不要物"，逼出整理决策。
- ③默认假设：暂不定夺的物可挂红牌暂存区，限时裁决。
- ④触发：要/不要难决、现场积压。
- ⑤前置：5S 整理启动。
- ⑥不该用/误用：红牌挂了不裁决（红牌区变新垃圾场）。
- ⑦掩盖：清了不要物但"要的物"仍乱放（未到整顿）。

**定置管理（Fixed-Position Management）** `[行业实践]`
- ②真正解决：物有其位、位有其物、物有其量，消灭"找东西"的浪费。
- ③默认假设：位置可被定义且被遵守。
- ④触发：同物多放、用时找不到。
- ⑤前置：5S 整顿、目视。
- ⑥不该用/误用：定位后无归位纪律。
- ⑦掩盖：定置好但"该不该有这么多"未审（量的问题）。

### 1.9 计划与供应链层

**生产计划三层（长/中/短期计划）** `[行业实践]`
- ②真正解决：把"战略产能(长期)→MPS(中期)→排产(短期)"分层，避免用短期调度对抗长期失衡。
- ③默认假设：计划可分层、各层有不同时间粒度与决策主体。
- ④触发：排产天天插单、产能长期错配。
- ⑤前置：需求、产能、BOM 数据。
- ⑥不该用/误用：只有日排产无 MPS（被动救火）；用 MPS 当日调度。
- ⑦掩盖：计划分层完善但执行(标准作业/换型)跟不上，计划再好也落空。
- 操作参数见分册：`04 supply-chain.md`（生产计划三层、MPS/MRP/CRP）。

**MPS（主生产排程）** `[学术/标准]`
- ②真正解决：把需求翻译成可执行的"何时产多少"，衔需求与物料/产能。
- ③默认假设：需求可聚合、产能可承诺。
- ④触发：缺料与积压并存、CRP 超载不知。
- ⑤前置：BOM、产能、提前期。
- ⑥不该用/误用：MPS 脱离 CRP（排了做不出）。
- ⑦掩盖：MPS 准但供应商交付不稳，仍断料。

**节拍排产（Takt-based Scheduling）** `[丰田官方]`
- ②真正解决：按 T/T 排产，使产出节奏匹配需求，避免过量。
- ③默认假设：可按节拍匀速产出。
- ④触发：前松后紧、月末冲产。
- ⑤前置：T/T、平准化。
- ⑥不该用/误用：需求波动大时无平准硬排节拍。
- ⑦掩盖：节拍排产对换型/质量波动零容忍。

**拉动式计划（Pull Planning）** `[丰田官方]`
- ②真正解决：以后工序消耗驱动前工序，减少推式库存。
- ③默认假设：下游消耗可规则传递、上游可信赖。
- ④触发：推式导致高库存仍断线。
- ⑤前置：看板、超市、平准。
- ⑥不该用/误用：供应商不稳就拉动（被放鸽子即断）。
- ⑦掩盖：拉动让在制 capped，但不解决"需求本身不合理"。

**供应链延迟（Supply Chain Lead-time）** `[学术/标准]`
- ②真正解决：识别并压缩从下单到入库的总提前期，降低所需安全库存。
- ③默认假设：提前期可测、可压缩。
- ④触发：原材料库存高、供应商周期长。
- ⑤前置：供应商数据、期量标准。
- ⑥不该用/误用：只压本厂不压供应商（杯水车薪）。
- ⑦掩盖：压缩提前期不解决"需求波动"本身。

**牛鞭效应（Bullwhip Effect）** `[学术/标准]`
- ②真正解决：解释"下游小波动→上游大震荡"的需求放大，指导用信息共享/小批量/VMI 抑制。
- ③默认假设：多级供应链中信息延迟与批量放大是主因。
- ④触发：越上游库存/排产波动越大。
- ⑤前置：多级供需数据。
- ⑥不该用/误用：本地优化各节点（各自安全库存加剧波动）。
- ⑦掩盖：牛鞭是现象，根因在"信息不共享+大批量订货"，单点改善无效。
- 来源注：牛鞭效应由 Lee et al. (MIT Sloan Management Review, 1997) 形式化 `[学术/标准]`；本地 01–08 分册未覆盖此主题（见 master SKILL §7.1 缺口），本文件补入。

### 1.10 改善与管理层

**A3 一页纸报告（A3 Report）** `[丰田官方]`
- ②真正解决：把"背景-现状-目标-根因-对策-结果"压在一页，逼思维结构化、对齐。
- ③默认假设：复杂问题可一张图说清；思考过程比结论重要。
- ④触发：汇报冗长、结论与过程脱节。
- ⑤前置：有真实数据、PDCA 思路。
- ⑥不该用/误用：A3 当模板填空、无对话（A3 是"对话媒介"非"交差文档"）。
- ⑦掩盖：A3 漂亮但数据假，形式合规掩盖内容空洞。
- 操作参数见分册：`03 hoshin-daily-5s.md`。

**PDCA / SDCA** `[学术/标准]`
- ②真正解决：PDCA=改善（标准不够好）；SDCA=维持（标准没被执行）。二者顺序：先 SDCA 稳定再 PDCA 提升。
- ③默认假设：先有稳定标准才有改善资格（不先标准化就无改善基线）。
- ④触发：标准未执行却上大项目；或只维持不改善（僵化）。
- ⑤前置：标准作业存在。
- ⑥不该用/误用：**把维持问题当改善问题（SDCA vs PDCA 混淆）**——典型如"用 6σ 大项目治'标准都没执行'"。
- ⑦掩盖：只 PDCA 不 SDCA，改善成果反弹。

**方针管理（Hoshin Kanri）** `[丰田官方]`/`[行业实践]`
- ②真正解决：把战略层层展开为可执行的年度目标+方策，聚焦有限重点。
- ③默认假设：目标应≤20 项且聚焦（丰田实践 `[行业实践]`）；下层目标比上层加严 10–15%。
- ④触发：目标写了没人做、部门各自为战。
- ⑤前置：高层共识、日常管理体系。
- ⑥不该用/误用：目标列 50 项（无重点）；只分解指标不分解方策。
- ⑦掩盖：方针漂亮但日常管理体系弱，年度目标落不了地。
- 操作参数见分册：`03 hoshin-daily-5s.md`。

**改善提案 / 创意功夫（Kaizen Suggestion）** `[行业实践]`
- ②真正解决：把改善常态化、全员化，涓涓细流汇成年化收益。
- ③默认假设：一线最懂浪费在哪；小改善累积胜过大项目。
- ④触发：改善只靠少数工程师；提案推不动。
- ⑤前置：评价/奖励/发表机制。
- ⑥不该用/误用：**只重数量不重实施**（废品提案）；提案"先提后做"而非"实施完毕才提"。
- ⑦掩盖：提案多但无标准化沉淀，改善不固化。
- 操作参数见分册：`03 rollout-talent.md`、`08-C`。

**QCC / QC 七大手法（Quality Control Circle / 7 QC Tools）** `[学术/标准]`
- ②真正解决：用查检/层别/柏拉/鱼骨/直方/散布/管制做数据驱动的问题定位。
- ③默认假设：问题可被数据分层与归因；少数主因贡献多数影响（Pareto）。
- ④触发：不良反复、主因不清；需建 SPC。
- ⑤前置：有数据、先层别再分析。
- ⑥不该用/误用：**柏拉图"其他项"过高仍下结论**（需再分层）；**管制界限当规格界限用**（CL±3σ 是过程能力，非客户规格）。
- ⑦掩盖：工具用对但数据本身不稳定/未分层，结论仍错。
- 操作参数见分册：`06 qc-seven-tools-old.md`、`07 qc-new-tools-and-qcc.md`。

**6σ（Six Sigma）** `[学术/标准]`
- ②真正解决：用 DMAIC + 统计，把过程缺陷压到 3.4 DPMO（6σ，含 1.5σ 漂移 `[学术/标准]`），治"系统能力不稳"。
- ③默认假设：变异是质量成本主源，可用统计量化并消除。
- ④触发：过程稳定但 Cpk 低、缺陷成本高、需黑带级项目。
- ⑤前置：数据充分、过程已稳定（先 SPC 判稳）。
- ⑥不该用/误用：**用 6σ 治"标准没执行"的维持问题**（应 SDCA/日常管理）；在小数据/非稳定过程上硬套。
- ⑦掩盖：6σ 项目宏大，会挤占日常改善资源，且常由专家主导、一线不参与（不可持续）。
- 注：本地 08-B 把 6σ 列入 13 工具之一，操作参数见该分册；本文件仅给选型边界。

**8D（Eight Disciplines）** `[行业实践]`/`[学术/标准]`
- ②真正解决：对重大/流出不良做结构化围堵+根因+再发防止，跨职能闭环。
- ③默认假设：问题需跨职能、有客户影响、要防再发。
- ④触发：客户抱怨、重大不良、重复发生。
- ⑤前置：有团队、数据、时限纪律。
- ⑥不该用/误用：小问题也开 8D（过度工程）；D3 围堵不做直接根因（不良继续流）。
- ⑦掩盖：8D 闭环但标准未更新，根因回归日常即复发。
- 操作参数见分册：`05 quality-management.md`。

### 1.11 数字化层（诚实评估，不吹）

**MES（制造执行系统）** `[行业实践]`
- ②真正解决：把订单-工序-设备-质量数据实时贯通，提供执行层可见性与追溯。
- ③默认假设：流程已相对清晰、数据定义统一，系统才能产生价值。
- ④触发：靠人工报工不准、追溯难、在制不可见。
- ⑤前置：**先精益简化流程**（否则 MES 放大现有混乱）；数据定义统一。
- ⑥不该用/误用：**上 MES 前没先简化流程**（数字化放大垃圾流程，garbage in/out）；为"数字化指标"而数字化。
- ⑦掩盖：MES 让数据好看，但真实停滞/换型/质量根因仍在线下，屏幕亮≠改善发生。
- 操作参数见分册：`04 digital-it.md`（MES 三层模型、机会识别双矩阵）。

**Andon 数字化（Digital Andon）** `[行业实践]`
- ②真正解决：把异常信号从"灯"升级为"可记录/可分析/可升级"的数据流，支撑响应 SLA 与趋势分析。
- ③默认假设：异常数据有价值，且能反哺根因改善。
- ④触发：纸质/灯光安灯无法统计、响应无追踪。
- ⑤前置：线下安灯机制已建立（响应 SLA 已有）。
- ⑥不该用/误用：数字化安灯但无响应闭环（只是电子警报墙）；为 KPI 压低异常上报。
- ⑦掩盖：数字化让异常"可数"，但若不闭环，数字漂亮问题照旧。

**看板数字化 / 电子看板（E-Kanban）** `[行业实践]`
- ②真正解决：把实体看板信号电子化，加速传递、便于跨厂/远距离补货。
- ③默认假设：信号闭环逻辑与实体看板一致（取走→触发补）。
- ④触发：多厂/远距离、实体看板传递慢。
- ⑤前置：平准化、拉动逻辑已跑通（实体版先验证）。
- ⑥不该用/误用：**没有信号闭环/没有 FIFO 的电子看板**（只是屏幕展示）；实体拉动未验证就数字化。
- ⑦掩盖：电子看板流畅但拉动逻辑错（如没平准），只是更快地把错误传遍。

**数据采集与 SPC 数字化（Data Acquisition + SPC）** `[学术/标准]`
- ②真正解决：自动采数让微停/降速/变异"被看见"（人常漏记微停），SPC 在线判异。
- ③默认假设：自动采数比人准；过程应先稳定再谈能力。
- ④触发：OEE 性能损失算不清（微停未记录）；管制图靠人手点。
- ⑤前置：设备可联网、有采集点定义；先判稳。
- ⑥不该用/误用：不稳定过程上 SPC（判异无意义）；采数不定义"好件/停机"口径（OEE 失真）。
- ⑦掩盖：采数全但无人分析行动，变成"数据坟墓"。

**工业物联网 IIoT 在精益中的角色** `[行业实践]`
- ②真正解决：提供实时、细粒度的设备/物料状态数据，是精益的"感官延伸"，放大 visibility。
- ③默认假设：更多数据→更早发现浪费与异常（前提是有人用）。
- ④触发：人工点检覆盖不到、微损不可见。
- ⑤前置：有改善组织去消费数据。
- ⑥不该用/误用：**把 IIoT 当"精益替代品"**（物联网不改善流程，只暴露流程；固化错流程更糟）；为采集而采集无业务问题。
- ⑦掩盖：IIoT 项目亮眼，但"改善能力（人）"未建，数据无人转化为行动。
- 诚实结论：数字化/IIoT 在精益中是**赋能层而非驱动层**——它放大既有流程的好坏，不能替代 VSM/SMED/自働化/标准作业等"流程改善"本身。先 lean 再 digital，顺序不可反。

## 2. 选型决策树（最高价值：问题 X → 上什么工具 → 为什么不是别的）

> 通用分叉框架：
> **第一层**：流不动（停滞/在制高）/ 做不快（C/T 超 T/T）/ 做不稳（波动/不良）/ 做不动（设备/人缺）。
> **第二层**：根因在 数据 / 流程 / 设备 / 人 哪一类？
> **第三层**：对应工具 + 为什么不是别的工具。
> 判据数字带 `[推断]` 者为启发式基线，须以本厂数据校准。

### 树 1 · 交期长 / 订单延期
```
现象：L/T ≫ 客户要求
└─ L1 增值比 = 增值时间 / L/T ？
   ├─ 增值比 <5%（离散制造典型 [推断]）→ 问题在"停滞"不在"加工"
   │   └─ 画物与情报流程图，看库存三角累计时间
   │      ├─ 情报前置时间占比 >50% [推断] → 情报流/计划慢
   │      │   └─ 生产计划三层 + 拉动式计划（不是先上设备）
   │      └─ 在制库存三角高、超市爆 → 流动阻塞
   │          └─ 单件流/单元生产 + 看板拉动（不是先压加工速度）
   └─ 增值比正常但各工序 C/T > T/T → 问题在"做不快"
       └─ L2 损失构成（OEE 拆解 / 16 大损失）
          ├─ 换型损失占工序时间 >30% [推断] → 上 SMED（不是线平衡！换型会打碎平衡）
          ├─ 时间稼动率低（停机/故障）→ TPM 自主保全（不是加人）
          └─ 纯手工操作慢 → 标准作业 + 动作经济（不是买设备）
关键判据：先算增值比区分"停滞型"与"加工型"；停滞型上 VSM，加工型才上 SMED/平衡。
```

### 树 2 · 库存高 / 资金周转慢
```
现象：库存周转天数高、资金占压
└─ L1 是"为不确定性囤"(安全库存过高) / "为批量囤"(EOQ/换型) / "流动阻塞"(节奏不一)？
   ├─ 换型时间长 → 大批量是被迫 → 先 SMED 缩批量（治本），再降库存
   │   └─ 若直接砍库存不压换型 → 断线（不是治本）
   ├─ 需求波动大 + 推动排产 → 平准化 + 看板拉动
   │   └─ 若没平准硬拉 → 波动冲垮上游（看板失效）
   ├─ 超市水位持续 > 补货点 → 看板张数/补货规则设错 或 FIFO 失效
   └─ 原材料库存高 + 供应商准时率低 → 供应链延迟/供应商管理
       └─ 此时上内部看板无效（根因在外部，先治供应链）
关键判据：先问"库存是哪种因"——换型因→SMED；波动因→平准；外部因→供应链。库存是结果不是原因。
```

### 树 3 · 不良率高 / 客户抱怨
```
现象：不良率高 / 客户抱怨
└─ L1 不稳定(同线时好时坏) / 系统性偏移(一直差)？
   ├─ 管制图有异常点/趋势 → 先稳（8D/快速反应找特殊原因）→ 再谈能力
   │   └─ 不稳定时上 6σ/Cpk 改善无意义（数据没稳态）
   └─ 稳定但 Cpk <1.0 [学术/标准 汽车行业常取 ≥1.33] → 系统性能力不足
       └─ 设备/工艺改进（不是检验能救）
          ├─ Cpk 1.0–1.33 → 自工序完结 + 防呆
          └─ L2 不良流出到客户(逃逸) / 停在线内？
             ├─ 流出的 → 自工序完结/防呆/安门+安灯（不是加终端检验）
             └─ 线内检出 → 标准作业/工序能力
                └─ L3 标准存在但人没照做？ → 日常管理/OJT（SDCA，不是上 6σ）
关键判据：先判稳不稳、判流出没流出、判标准执不执行；三道关不过，任何大项目都白搭。
```

### 树 4 · 设备故障多 / OEE 低
```
现象：OEE 低（Nakajima 行业典型约 60% [学术/标准]）
└─ 先拆 OEE 三率（时间稼动 / 性能 / 良品）
   ├─ 时间稼动低（停机/换型）→ 自主保全(清紧固)+计划保全
   │   └─ 若重复故障 → 计划保全+备件管理（不是加操作工）
   ├─ 性能低（微停/降速）→ 速度损失，常因微停未记录
   │   └─ 先数据采集(数字化)暴露微停 → 再个别改善（不上采集则微停隐形）
   └─ 良品率低（设备致不良）→ 设备精度/夹具 → 计划保全+质量
关键判据：OEE 低先分解三率，别笼统"抓设备"；时间低→保全，性能低→先采集可视化。
```

### 树 5 · 现场乱 / 管理混乱
```
现象：现场乱、东西找不到、板子过期
└─ L1 没有标准 / 有标准不维持？
   ├─ 连"要/不要"都分不清 → 5S 整理先行(红牌作战)
   │   └─ 若只大扫除不做整顿/素养 → 一个月回潮
   └─ 标准有但乱 → 定置管理 + 目视化 + 红牌
      └─ L2 物乱 / 信息乱？
         ├─ 物品没定位 → 5S/定置
         └─ 状态看不清 → 目视/安灯/管理板
关键判据：红牌作战后一个月又回潮 → 说明无 SDCA 维持机制，5S 必反弹，必须配日常管理与点检。
```

### 树 6 · 人工成本压力 / 要减人
```
现象：要减人、压人工成本
└─ L1 真效率低(过量生产/等待/搬运) / 假效率(已近需求极限还压人)？
   ├─ 真效率：有库存/等待 → 单件流/单元/少人化（用更少人做刚好的量）
   │   └─ 若直接裁人 → 断线/质量崩（不是真改善）
   └─ 假效率：C/T≈T/T 且满负荷 → 先改善(不然减人=把人累坏)
      └─ L2 线平衡差 / 换型多 / 多能工不足？
         ├─ 编成效率 <90% [行业实践] → 线平衡/山积图
         ├─ 换型频繁 → SMED
         └─ 工序间不能互替 → 多能工/OJT
关键判据：若"人均产出高但库存也高" → 假效率，减人无效甚至有害；少人化靠"减浪费"不是"减人头"。
```

## 3. 工具组合拳（顺序敏感：为什么顺序不能换）

> **📌 playbook 权威版本在 `SKILL.md` §10.4**（10 条决策启发式）。本节记录工具**顺序**的推导，
> 与 §10.4 的 P1–P10 决策规则配套使用：§10.4 说"该上什么"，本节说"按什么顺序上"。

> 核心规律：**先治本（换型/稳定/标准/源头），再上放大层（平衡/降库存/数字化/减人）**。顺序反了，放大的是缺陷。

1. **SMED → 线平衡**：先压换型缩批量，再谈平衡。原因：换型损失会持续打碎任何线平衡；不先压换型，平衡成果随换型波动化为乌有。
2. **标准作业 → 改善（PDCA）**：先有"当前最优标准"再改善。原因：无标准 = 无基线，改善无法量化验证；改善成果也无处固化（SDCA 缺失必反弹）。
3. **自働化/防呆 → 降库存**：先能停线、不流出不良，再减缓冲。原因：降库存会暴露所有波动与不良；若源头止不住，降库存=把缺陷直接推给客户/停线灾难。
4. **5S/定置 → 目视化 → 日常管理**：先整理整顿，再让状态可见，最后用日常管理维持。原因：没整理就目视=在垃圾上贴标签；没维持机制目视板必过期。
5. **VSM 现状 → 未来状态 → 拉动**：先看清现状停滞，再设计未来，再上拉动。原因：没现状图就拉动=盲拉；没未来图就拉动=无目标地 capped 在制。
6. **平准化 → 看板拉动**：先均衡需求，再看板。原因：不平准硬拉，需求波动直接冲击上游，看板从"信号"变"噪声放大器"。
7. **TPM 自主保全 → 计划保全**：先操作工守基本状态（清紧固），再专业保全。原因：自主保全不做，保全人员被日常清洁拖死，计划保全无从谈起。
8. **方针管理 → 日常管理**：先定有限年度目标与方策，再落日常点检维持。原因：无方针，日常管理在救火中淹没有限目标；无日常，方针落不了地（两者是战略-战术关系，不可缺一）。
9. **SDCA → PDCA**：先维持标准（SDCA）稳定，再改善（PDCA）提升。原因：把维持当改善（如用 6σ 治"标准没执行"）是本末倒置，改善成果也守不住。
10. **源流质量/自工序完结 → 检验削减**：先在源头做对、不流出，再削减下游检验。原因：先减检验=放不良流出；源头做对后检验才成为冗余可削。

## 4. ⚠️ 反模式清单（外行才会犯的错，共 25 条）

> 每条：错误做法 → 为什么错 → 正确做法。

1. **先上工具再诊断（拿看板当装修）**
   错：没做 VSM/价值流诊断就上工具，工具成摆设。为什么错：工具是"对症的药"，不诊断就开药治不到根。对：先 VSM/物与情报流程图定位最大停滞段，再选工具。
2. **把看板做成展示看板（失去信号闭环）**
   错：看板只显示"在产/进度"，无"取走才补"的触发。为什么错：看板本质是取料/生产指令信号，无闭环=装饰，在制不被 capped。对：实体/电子看板必须有"后取前补"信号闭环 + FIFO。
3. **用看板硬拉生产却没做平准化**
   错：需求波动大时直接上拉动。为什么错：波动被看板原样传给上游，上游被冲垮，拉动失效。对：先 SMED 压换型 + 平准化平滑需求，再拉动。
4. **5S 做成大扫除运动**
   错：季度突击打扫，过后回潮。为什么错：5S 是"维持标准的素养"，大扫除不治本、不建机制。对：5S 六步 + 红牌 + 定置率 + 日常管理维持，素养层是核心。
5. **上 6σ 解决"标准都没执行"的维持问题（SDCA vs PDCA 混淆）**
   错：标准都没人照做，却开黑带大项目。为什么错：这是维持(SDCA)失败，不是能力(PDCA)问题；大项目掩盖"日常管理缺位"。对：先 SDCA/日常管理/培训，标准执行稳了再谈改善。
6. **SMED 只做内作业不做外作业（治标）**
   错：只压缩机内换型时间。为什么错：外作业(准备/预热)仍在停机窗口做，收益天花板低。对：先内/外分离→转内为外→并行→再压缩，全链路做。
7. **用 OEE 考核个人（把人变成看机器的）**
   错：把 OEE 当个人 KPI。为什么错：诱发瞒微停、抢产忽视质量，与自働化"异常要停"相悖。对：OEE 是设备/产线指标，用于定位损失类型，考核看团队与改善。
8. **超产被当成好事**
   错：产量超计划被表扬。为什么错：超出 T/T 需求的产出=库存/等待浪费（假效率），是七种浪费之一。对：以"刚好满足需求 + 零停滞"为真效率，超产视为问题。
9. **效率改善优先于质量改善**
   错：先压节拍提效率，质量让步。为什么错：不良返工吞噬效率收益，且不良流出损失远大于效率。对：质量优先（自工序完结/防呆），再提效率。
10. **自动化当作改善（自动化不改善流程，只固化流程）**
   错：上一堆自动化设备当"精益成果"。为什么错：自动化只是把现有流程固化——固化一个错的流程更糟（jidoka 前提是先手工 kaizen 消除 muda/mura/muri）。对：先手工改善消除三 MU，再做带人智慧的自动化（自働化）。
11. **一次性大项目式精益（缺乏标准化的改善会反弹）**
   错：请顾问做几个月大项目，结束后回潮。为什么错：无 SDCA 固化，改善成果随项目结束消失。对：改善日常化（提案/QCC/日常点检），以小步持续为主。
12. **培训替代现场辅导**
   错：课堂培训完就认为"会了"。为什么错：课堂懂≠现场会，技能靠 OJD"先做给看→做给看→做做看"。对：培训+现场带教+得星表认证，标准作业是教材。
13. **精益顾问代替现场人员做诊断（违反三现主义/复地现物）**
   错：顾问在会议室分析、代写方案。为什么错：改善必须现场人员 own（genchi genbutsu），否则不可持续、不落地。对：顾问做教练，现场人员做诊断与改善。
14. **用看板数量倒推库存而不做需求波动分析**
   错：套张数公式直接定库存。为什么错：安全库存须基于需求/提前期波动；不分析波动，库存错配（缺料或积压）。对：补货规则 = 周期×用量 + 基于波动的安全量，先量化波动。
15. **为了 JIT 而 JIT，忽略供应商交付稳定性**
   错：内部强推拉动但供应商常延迟。为什么错：拉动前提是上游可信赖；供应商不稳，拉动即断料。对：先治供应链（交付稳定/小批量供货），再拉内外部。
16. **把"人均产出"提升当作改善成果（可能是把人累坏了）**
   错：人均产出涨了就报喜。为什么错：可能是加班/强度堆出来的假效率，伴随质量/离职风险。对：看真效率=单位人力产出刚好的量 + 停滞/库存是否降。
17. **把管制界限当规格界限用（SPC 误用）**
   错：用客户规格 ± 当管制界判异。为什么错：管制界 CL±3σ 是过程能力，规格是客户要求；混用导致判异失效或误判。对：先 SPC 判稳，再看 Cpk 对规格的能力。
18. **柏拉图"其他项"过高仍下结论**
   错：其他项 > 关键项就定主因。为什么错：其他项藏着未分层的主因。对：其他项高须再层别(4M1E)拆分后再判。
19. **上 MES/数字化前没先简化流程**
   错：流程混乱就上系统。为什么错：数字化放大现有流程（garbage in/out），混乱被系统化。对：先 lean 流程简化，再 MES 固化与放大。
20. **电子看板但没有信号闭环 / 没有 FIFO**
   错：屏幕显示库存但无取补触发。为什么错：只是可视化，不是拉动；无 FIFO 则批次乱。对：电子看板逻辑必须与实体拉动一致（取→触发补）+ FIFO。
21. **把"减少在制品"当目的本身**
   错：强压在制不顾换型/设备能力。为什么错：换型没压、设备不稳，强压在制=断线。对：在制降低是 SMED/平准/稳定后的结果，不是起点。
22. **方针管理目标太多（>20 项）导致无重点**
   错：年度目标列几十项。为什么错：资源稀释，无一落实（丰田实践目标≤20 `[行业实践]`）。对：聚焦有限重点 + 方策 + 加严展开。
23. **改善提案只重数量不重实施**
   错：比提案数。为什么错：催生废纸提案，无价值沉淀。对：提案"实施完毕才提"，看实施率与年化效益。
24. **把"省人化"当"少人化"**
   错：为减人而减人。为什么错：省人化=减人头（可能牺牲弹性/质量）；少人化=用更少人做刚好的量且能随需求增减。对：目标是少人化（弹性），靠消除浪费而非砍人。
25. **用自动化/机器人解决"节拍不平衡"**
   错：线不平衡就堆设备。为什么错：不平衡是线平衡/多能工问题，设备只是把不平衡固化且更贵。对：山积图找瓶颈 + 重分配 + 多能工，必要时才补设备。

## 5. 工具选择成熟度判断（30 分钟车间快诊）

> 资深人走进车间 30 分钟，靠以下 5 问判断"工具用得对不对"：

1. **"这条线换一次型要多久？谁记的？"**
   → 若答不出具体数 / 没人记录 → 换型未管控，SMED 与数据采集缺失；看板拉动必受其累。
2. **"在制品堆在哪？为什么堆在这？"**
   → 若答"一直都这样" → 无停滞意识，未在 VSM/标准手持层面管控，流动层工具缺位。
3. **"这块板（标准作业/目视/安灯）谁负责更新？最后更新是什么时候？"**
   → 若板子过期/无人更新 → SDCA 维持机制失效，5S 与标准作业在反弹边缘。
4. **"异常发生时谁停的线？停了多久、怎么响应的？"**
   → 若从不/很少停 → 自働化/安灯形同虚设，不良在流出；或产量 KPI 压过了异常响应。
5. **"你上个月改善的标准作业改了哪一条？"**
   → 若标准长期不变 → 改善未闭环，PDCA 没转；所谓"精益"停在表面工具。

> 判读：5 问中若有 ≥3 问答不出/答非所问，则"工具用得不对"——多为反模式 1/11/13（先工具后诊断、大项目式、顾问代做）所致，应先回到 VSM + SDCA 地基，而非继续堆工具。

## 二、高优先级缺口（1 项）

### ❌ 认知层零测试覆盖

**问题**：`test-prompts.json` 的 35 条测试**全部是 v1.x 执行层场景**（工具/公式/推行步骤）。
v2.0 新引入的内容——**7 处事实校正、6 个心智模型、25 条反模式、智识谱系争议**——一条测试都没有。

**为什么严重**：这7 处事实校正是本skill 最有价值的产出。如果 skill 在真实对话中
被追问"精益五大原则是谁提出的"，它可能**重新说出"丰田官方定义"**——等于把刚纠正的
错误又传播出去，而用户看不到哪个分支被触发。

**master-skill 依据**：Phase 4.1 已知测试 / 4.2 边缘测试 / 4.3 风格测试为必做项。

**建议**：新增 `test-prompts-v2.json`，至少 18 条（详见下文 §五）。

## 三、应修项（3 项）

### 1. frontmatter description 过长（1860 字符）

横向对比本机同类 skill：

| skill | description 长度 |
|---|---|
| amazon-review-mining | 194 字符 |
| qiaomu-anything-to-notebooklm | 129 字符 |

| html-ppt-skill | 617 字符 |
| chip-fa-analysis | 725 字符 |
| **lean-production-expert** | **1860 字符** ⚠️ |

**是最长的 2.5–3 倍。** description 是常驻上下文，占用高且会稀释检索命中。
建议压缩到 600–800 字符，把能力细则移到正文 §0。

### 2. 触发词中有 68 个高误触风险词

**短词类**：`5S` `6S` `A3` `OEE` `MES` `ERP` `TPS` `SPC` `8D` `Cpk` `QCC`
**通用英文词类**：`kaizen` `jidoka` `takt` `gemba` `smed` `andon` `heijunka` `poka-yoke` `lean` `vsm`

问题在于：`A3`（日常指A3 纸/思维工具）、`MES`（系统名）、`8D`（数字）、`5S`（可指5S 法则之外的量词）
都是**日常或跨领域高频词**，可能与本领域无关的对话撞车。

**建议**：短词保留但要求**与精益词共现**才激活（如"5S"→"5S 现场/5S 管理"）；
纯英文缩写降权或移入第二组triggers。

### 3. Changelog 只记「新增」，未记「修正」

master-skill Phase 0C 要求更新时标注 **changed / deprecated**，让使用者知道
哪些旧说法不再成立。本skill v2.0 至少有三项changed：

| 项 | v1.x 说法 | v2.0 修正 |
|---|---|---|
| OEE 85% | "世界级 >85%" | Nakajima 的**拉伸目标**（0.90×0.95×0.99），非行业中位数 |
| 五大原则 | 隐含"丰田官方定义" | **沃麦克/琼斯的重构** |
| 14 原则 | "丰田 14 项管理原则" | **莱克的学者归纳** |
| 分册字数 | "约 89 万字" | **47.1 万字**（字节数误记为字符数） |

**已在 §10.1 / §13.5 记录，但未进 Changelog 表格**——只看 Changelog 的人会错过。

## 五、审查中发现并已修复的问题

### 🔧 CLI 报告丢段（真bug，已修）

`cli/decision/tool-select.sh` 的报告生成里：
```bash
recommend "$scene" | sed 's/^/    /'     # ✗ 输出到 stdout，mdbuf 拿不到
```
`recommend` 内的 `mdbuf_add` 写入发生在管道子shell，**markdown 报告的「推荐路径」整段为空**。

**已修为**：
```bash
rec_out="$(recommend "$scene" | sed 's/^/    /')"
while IFS= read -r rec_line; do mdbuf_add "$rec_line"; done <<< "$rec_out"
```
并给 `static-check.py` 增加了这一 bug 类的检测（只在该 while 块内确有写入时才报，避免误报）。

> 这是"未真机运行"的直接代价——静态检查通过了，功能却仍有bug。
> **强化了 §12.1 的结论：bash 脚本必须真机跑一次。**

### 误报澄清（不是问题）

- `common.sh` 提到 `jq` → 只是注释「不要求 jq」，未实际调用
- `fact-check.sh:107` 管道 while → 只printf 到 stdout，不写 mdbuf，安全
- `awk` / `sed` / `date` → 均属 POSIX，非 spec 意义上的违规

# 精益屋 Lean House —— skill 图标设计说明

> **文件**：`icons/logo.png`（200×200 PNG）+ `icons/logo.svg`（矢量源）
> **生成**：`tools/make_icon.py`（纯 Pillow 手绘矢量，不调用任何图像生成 API）
> **校验**：`tools/verify_icon.py`（frontmatter `icon` 字段 ↔ 文件一致性）

---

## 一、为什么选「精益屋」而不是齿轮

图标要传递的是**这个领域是什么**，不是"跟制造有点关系"。

| 候选图形 | 判断 |
|---|---|
| 齿轮 / 扳手 | ❌ 只表示"制造/维修"，不表示"精益"。任何工业 skill 都能用，没有区分度 |
| 箭头循环 | ❌ 泛用于"流程/迭代"，语义过宽|
| 七大浪费清单 | ❌ 200px 下无法呈现 |
| **精益屋 Lean House** | ✅ **丰田 TPS 唯一公认的专属结构符号**，且天然是一个"结构图"而非"物件图" |

精益屋的优势在于：它把 TPS 的**结构**编码进一个图形——目的、两大支柱、基础三层关系一目了然，
而且这个符号在精益领域**没有歧义**。

## 二、图形语义逐层拆解

```
        ▲白色屋顶
       ╱──────╲
      ╱        ╲          = 顾客价值 / 目的（Value from the Customer）
     ▬▬▬▬▬▬▬▬▬▬         = 琥珀过梁：价值向下传递
     ▮     ▮            = 双柱：准时化 JIT（左）+ 自働化 Jidoka（右）
    ▮       ▮               —— TPS 两大支柱，互锁不可拆
   ▬▬▬▬▬▬▬▬▬▬▬▬▬       = 地基：标准作业 / 稳定 / 目视化 / 方针管理
```

| 元素 | 颜色 | 语义 | 设计作用 |
|---|---|---|---|
| 屋顶 | 白 `#FFFFFF` | 顾客价值 / 目的 | 最高、最亮，视觉重心= "一切为了客户价值" |
| 过梁 | 琥珀 `#FACD15` | 价值向下传递 | **连接屋顶与双柱**，避免上部元素悬空漂浮 |
| 双柱 | 青 `#38BDF8` | 准时化 JIT + 自働化 Jidoka | TPS 的两根支柱，一眼可数=2 |
| 地基 | 蓝灰 `#96B4D8` | 标准作业 / 稳定 / 目视化 | 最宽最沉，压住画面重心 |
| 底| `#172A47`→`#0C1A2D` | — | 深海军蓝渐变，与本机其他 skill 图标**不撞色** |

## 三、迭代过程（依据渲染后视觉复核）

共 3 版，每版都渲染后**实际看图**再修：

| 版本 | 问题 | 修法 |
|---|---|---|
| v1 | 屋顶下沿呈"人字形雪佛龙" + 外飞檐，底部空旷 | 加陡屋顶、双柱加粗、收紧竖向节奏 |
| v2 | **仍读成"马戏帐篷"**——飞檐外飘 + 屋顶与琥珀条之间有悬空缝隙 | 屋顶改**实心三角山墙**，琥珀改为紧贴屋顶下沿的**过梁** |
| **v3（当前）** | — | 实心三角 unmistakably 是屋顶；结构连贯"屋顶—过梁—双柱—地基" |

**教训**：图标不能"画完就交"。v1 和 v2 的代码逻辑都没错，但**视觉语义是错的**——
必须渲染出来看。这次是靠 `Read` 工具把 PNG 读回来看，才发现了"帐篷"问题。

## 四、技术规格

| 项 | 值 |
|---|---|
| 输出尺寸 | 200×200 px（对齐 `linkfox-amazon-ads/icons/logo.png` 规格）|
| 格式 | PNG（`optimize=True`）+ SVG 源文件 |
| 抗锯齿 | 4× 超采样（800×800）→ LANCZOS 降采样 |
|圆角 | 半径 = 边长 22%（对齐 linkfox 的 app icon 风格）|
| 最小可辨识尺寸 | **约 32 px**（skill 列表通常 ≥40 px）|
| 版权 | 原创矢量，无版权风险 |
| 积分消耗 | **0**（不调用图像生成 API） |
